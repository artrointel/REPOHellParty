# Apex Predator 플레이테스트

## 구현 방식

- 호스트만 `DuckFamily`와 `DuckClone`을 관리한다. 참가자에게 신규 프리팹이나 RPC를 요구하지 않는다.
- 순정 오리 프리팹과 `EnemyParent.SpawnRPC`/`DespawnRPC`, `Enemy.EnemyTeleported`를 사용한다. 분신에는 본체 컨트롤러를 붙이지 않는다.
- 분신 루트는 슬롯별로 재사용한다. 순정 디스폰 후 재스폰 시 체력을 복원하며, 실제 사망 후 30초 재소환은 순정 초기 체력을 사용한다.
- 분신은 순정 코어 생성 플래그를 끈다. 사망 가스는 순정 우라늄 가치품을 가치 0의 임시 매개체로 생성하고 순정 파괴 RPC로 가스 효과를 발생시킨다. 일반 코어·가치품·Cleanup Crew 가스는 수정하지 않는다.
- Crown은 순정 가치품을 머리 위에서 이동시키며 순정 위치 동기화를 사용한다. 본체 사망 시 고정을 풀고 기존 Crown을 보상으로 남긴다.
- 생성 시 순정 `LevelGenerator.EnemySpawn`과 같이 AI·물리 위치를 먼저 초기화하고, 실제 `SpawnRPC`가 완료된 뒤 능력을 시작한다. Crown 위치는 시선 제어용 Transform이 아닌 물리 몸체와 실제 메시 상단을 기준으로 계산한다.
- 현재 원격 호환성은 구현 설계이며 실제 미설치 참가자 테스트 완료를 의미하지 않는다.

## 실행 후 확인

오리 테스트용 추가 오리·총기 생성과 상태·호출 경로 진단 코드는 제거했다. 현재 Debug는 [Animal 테스트](animal-playtest.md)를 위해 난이도 5와 Animal·총기 생성을 제공한다. 아래의 실제 진행도 검증은 Release의 순정 생성 오리로 확인한다.

게임을 종료한 뒤 저장소 루트에서 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-RepoDev.ps1`을 실행한다. Debug 빌드·배포 후 게임 창이 표시된다. 일반 플레이 테스트에는 F5나 디버거 연결이 필요 없다.

1. Release에서 stage1이 난이도 0으로 시작하고, 테스트용 몬스터·총기가 추가되지 않는지 확인한다.
2. stage4/10/16의 순정 생성 본체만 Crown을 가지고 분신이 각각 최대 1/2/3마리까지 인지 없이 생성되는지 확인한다. 분신이 추가 분신을 소환하지 않는지 확인한다. Crown은 높이 벡터 70%, 몸체 정면 기준 뒤로 0.25m 보정을 적용한다.
3. 분신을 죽이면 코어 대신 가스가 남고 본체·다른 분신·플레이어가 순정 가스 피해를 받는지 확인한다.
4. 분신 3마리를 동시에 제거한다. 본체가 살아 있을 때 약 30·60·90초에 한 마리씩 보충되는지 확인한다.
5. 손상된 분신을 본체에서 15m 이상 떨어뜨린다. 순정 사라지는 애니메이션이 끝난 뒤 같은 인스턴스가 본체 옆에 재스폰하고 체력이 유지되며 가스·코어·쿨타임 초기화가 발생하지 않는지 확인한다. 15m 미만에서는 거리 복귀가 발동하지 않아야 한다. 기절 중이라면 순정의 기절 우선 처리 후 애니메이션이 진행되는지 확인한다.
6. 본체를 죽인다. 남은 분신도 죽고 가스를 남기며, 재소환이 중단되고 Crown을 집어 수집할 수 있는지 확인한다.
7. 수면총으로 본체·분신을 기절시켜 순정 상태 전환과 회수 이후 AI가 정상인지 확인한다.
8. 모드를 설치하지 않은 참가자와 위 항목을 반복한다. Crown 위치·수집, 분신의 이동·공격·사망, 가스 표시와 피해가 양쪽에서 일치하는지 확인한다.
9. Release에서 stage1~3의 자연 생성 오리가 Crown·분신 없이 순정 상태인지, stage4/10/16에서 상한이 각각 1/2/3인지 확인한다. 디버그 총기·추가 오리가 생성되지 않아야 한다.

분신은 안전한 인접 NavMesh 지점을 찾지 못하면 소환을 지연하고 재시도한다.
