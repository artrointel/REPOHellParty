# 몬스터 스폰 수량 보정

순정 수량 계산 결과에 아래 보정값을 더한다. 순정 스폰 시스템을 교체하지 않고 추첨 직전의 수량을 조정하며, 몬스터 능력 해금과는 별개의 전역 밸런스 규칙이다. 라운드 번호는 현재 스테이지 번호와 같다.

| 현재 라운드 | 참여 인원 1~6명 | 참여 인원 7명 이상 |
| --- | --- | --- |
| 1~4 | 중형 +1 | 중형 +2 |
| 5~9 | 대형 +1 | 대형 +2 |
| 10 이상 | 중형 +1·대형 +1 | 중형 +2·대형 +2 |

- 라운드는 순정 `RunManager.levelsCompleted + 1`이다. 재시도·이어하기는 복원된 완료 스테이지 수를 따르며 별도 카운터를 저장하지 않는다. 헬파티 능력 난이도나 테스트용 난이도 5 고정으로 수량 표의 라운드를 바꾸지 않는다.
- 인원은 `AmountSetup` 시점의 실제 접속자 수다. 호스트·사망한 참가자를 포함하고 Photon의 `IsInactive` 참가자는 제외한다. 싱글플레이는 1명이다. 도중 입퇴장은 이미 구성된 몬스터를 즉시 증감시키지 않으며 다음 구성 계산에 반영된다.
- 호스트·싱글플레이의 실제 수집 스테이지에만 적용한다. 순정 기준인 헬파티 난이도 0, 상점·로비·메뉴·아레나 및 참가자의 수량 계산은 변경하지 않는다.
- 순정 `EnemyDirector.AmountSetup()`이 수량 곡선을 평가한 다음, 추첨 전에 `amountCurve2Value`와 `amountCurve3Value`에 표의 보정값을 적용한다. 소형 수량은 그대로다. 몬스터 선정 순서·가중치·중복 처리·진행도 및 프로필 해금 조건, 출현 위치·등장 대기·디스폰·재등장은 순정 흐름을 사용한다.
- 추가 수량도 순정 `PickEnemies(enemiesDifficulty2/3)`가 추첨한다. 선정된 `EnemySetup`의 프리팹 구성은 그대로 사용하므로 순정 프리셋의 동반 오브젝트·무리 구성을 임의로 잘라내지 않는다. 보정 단위는 각 분류의 순정 추첨 슬롯이다.
- 순정 코드가 총수와 스폰 준비 수를 계산하고 등록하므로 별도 강제 소환이나 새 RPC를 사용하지 않는다. 바닐라 참가자는 추가 설치 없이 같은 몬스터를 본다.
- 해당 분류에서 선택 가능한 프리셋이 전혀 없으면 그 분류의 추가 슬롯만 건너뛰고 경고를 기록한다. 다른 분류의 유효한 보정은 적용한다. 잠긴 몬스터를 강제로 해금하거나 빈 프리셋을 생성하지 않는다.
- 순정 수량은 호출마다 곡선에서 다시 계산하므로 반복 초기화로 보정이 계속 누적되지 않는다. `Stage N (P players): native monster picks medium X -> Y, large A -> B.` 로그로 실제 인원·적용 전후 수량을 확인한다.

## 실제 확인

1. 기본 Debug 또는 Release로 1·4·5·9·10라운드를 생성하고 로그의 중형·대형 수량이 표와 일치하는지 확인한다. 순정 선정·등록 경로를 거쳐 나타나야 한다.
2. 6명·7명 경계에서 각각 확인한다. 10라운드에 7명이면 중형·대형 각각 +2여야 한다. 사망자는 인원에서 빠지면 안 되고, 비활성 참가자는 제외한다. 라운드 중 인원 변동으로 기존 몬스터가 갑자기 생성·제거되면 안 된다. 저장 이어하기·새 런·재시도도 확인한다.
3. 소형 수량과 순정 몬스터의 첫 등장 대기·사라짐·재등장이 유지되는지 확인한다. 추가 몬스터가 반드시 스테이지 시작 즉시 눈앞에 등장하는 기능은 아니다.
4. 호스트와 바닐라 참가자의 몬스터 구성·이동·공격이 일치하고, 스폰 준비 수 불일치로 로딩이 멈추지 않아야 한다.
5. 청소부 테스트 Debug의 별도 테스트 개체는 이 보정과 별개다. 실제 진행도와 자연 생성 구성의 비교에는 옵션 없는 기본 빌드를 사용한다.

순정 호출 지점·단계 경계·호스트 및 장면 조건·잠금 조건은 자동 검사하며, 실제 동시 출현 수와 체감 난이도는 플레이에서 확인한다. 관련 진행 규칙은 [공용 난이도](difficulty.md)를 따른다.
