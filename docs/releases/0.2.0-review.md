# HellParty 0.2.0 배포 전 검토

검토일: 2026-10-28. 검토 대상은 현재 소스에서 생성한 **Release DLL과 최종 Thunderstore ZIP**이다. 이 문서는 공개 업로드나 실제 멀티플레이 완료를 뜻하지 않는다.

## 결과

자동 검사·설치된 게임 호출 계약·정적 분석에서 배포를 막는 추가 문제는 발견하지 못했다. 규칙 및 어셈블리 검사 **1,075개**, 정상·변조 패키지 검사 **10개**를 통과했다. 기본 Debug·Release·청소부 테스트 Debug 모두 경고·오류 0개다.

- 청소부 테스트 코드는 개발 소스에 별도로 유지하지만 기본 Debug·Release에서는 컴파일하지 않는다. `HellParty.Debugging`의 중첩 타입까지 Release에서 검사했으며, 해당 타입을 참조하는 호출·테스트 시작 로그·임시 키보드 조작이 없다.
- Release 어셈블리의 구성 표시와 컴파일 최적화를 확인했다. 일반 진행도의 난이도 계산을 사용하며 테스트 시나리오의 강제 난이도 경로가 없다. 실제 능력인 몬스터 소환·무기 생성은 테스트 스폰과 구분해 유지한다.
- 최근 몬스터 수량 보정은 순정 수량 곡선 평가 후·추첨 전에 중형·대형 값만 변경한다. 1/4/5/9/10라운드 경계와 6/7명 인원 경계, 호스트·장면 조건, 순정 해금 조건을 검사했다. 잠긴 분류는 보정만 건너뛰고 순정 선택·위치·출현 시점·스폰 준비 수 계산을 사용한다.
- 패키지의 버전 `0.2.0`이 csproj·플러그인·manifest·DLL에서 일치한다. 의존성은 `BepInEx-BepInExPack-5.4.2305`이며, README·설명은 호스트만 설치하고 바닐라 참가자와 함께 플레이하는 장점을 전면에 안내한다.
- ZIP의 파일명·루트 배치·UTF-8·아이콘 PNG 형식/256×256 크기·manifest 항목·Release DLL 해시를 확인했다. 게임·Unity·BepInEx DLL, Debug DLL, PDB, 개발 스크립트, 설정·로그·소스는 포함하지 않는다.
- 잘못된 파일·중복·메타데이터·아이콘·DLL 등이 들어간 패키지를 검사기가 거부하는 회귀 검사도 통과했다.

## 이번 검토에서 보완한 항목

- 패키징 빌드에 `HellPartyTestScenario=None`을 명시했다. 작업 직전에 테스트 Debug를 빌드했어도 업로드 ZIP은 테스트 옵션 없는 Release에서만 생성한다.
- Release 구성·최적화·중첩 테스트 타입·테스트 호출/로그·테스트 단축키 제외 검사를 추가했다.
- 배포 README의 오래된 개발 설명을 실제 Release 제외 정책에 맞췄고, 0.2.0 CHANGELOG의 임시 후보 표기를 정리했다.

## 최종 ZIP 구성

```text
manifest.json
README.md
CHANGELOG.md
icon.png
BepInEx/plugins/HellParty/HellParty.dll
```

산출물은 `artifacts/HellParty-0.2.0.zip`, 체크섬은 `artifacts/HellParty-0.2.0.zip.sha256`, 검증 보고서는 `artifacts/HellParty-0.2.0.release.json`이다. ZIP과 내부 DLL의 최종 SHA-256은 해당 보고서에 기록한다. 검증 로그는 `artifacts/crown-release-verification.log`다.

## 확인 범위의 한계

- 최신 ZIP을 새 호스트 프로필에 설치한 뒤 바닐라 참가자와 진행하는 최종 플레이는 이번 검토에서 실행하지 않았다. 특히 7명 이상 인원 보정, 장시간 웨이브·부화 재사용, 헤드 원격 Grab·전달은 자동 검사만으로 결과를 확정할 수 없다. 기존 사용자 플레이 결과를 최신 패키지의 새 설치 검증으로 간주하지 않는다. JSON 보고서의 `in_game_multiplayer_verified`는 `false`로 유지한다.
- Thunderstore 공개 페이지·API에 연결하지 못해 `Artrointel-HellParty-0.2.0`의 기존 업로드 여부를 확정하지 못했다. 저장소에 지정된 0.2.0으로 ZIP을 생성했으며, 이미 같은 버전을 올렸다면 버전을 증가시켜 다시 패키징해야 한다. 실제 업로드·계정 작업은 수행하지 않았다.

패키지 요구사항은 [Thunderstore 공식 가이드](https://wiki.thunderstore.io/mods/creating-a-package)를 확인했다. 게임 플레이 확인 항목은 [배포 준비 문서](../release-readiness.md)와 [플레이테스트](../playtests/README.md)를 따른다.
