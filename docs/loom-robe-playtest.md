# Loom·Robe와 스토커 플레이테스트

Debug 프로필의 `[Debug.LoomRobe] Enabled = true`를 사용한다. Trudge·Headman·Clown·Reaper·Upscream·CleanupCrew·Huntsman은 false로 둔다. 이 시나리오가 최우선이며 난이도 **5**를 유지한다.

- 시작 지점 4~20m 내의 연결된 NavMesh에 **Loom 1마리·Robe 1마리**를 각각 준비한다. 한쪽 위치 탐색이 지연되어도 이미 생성한 다른 쪽을 중복 생성하지 않는다.
- 샷건·수면총도 각각 1개 준비한다. 이전 테스트 몬스터는 추가 생성하지 않는다.
- 스토커는 테스트 코드가 별도로 생성하지 않는다. 각 본체의 **실제 동반 생성 로직**으로 한 마리씩 등장해야 하므로 총 2마리를 확인한다. `Stalking Doll companion created for ...` 로그로 각각의 본체를 확인할 수 있다.
- **이번 테스트로 생성한 Loom에만** 생존자 2명 조건을 임시로 우회한다. 혼자여도 납치가 가능하며 자연 생성 Loom·Huntsman과 Release에는 적용하지 않는다. 4m·시야 ray·추적/공격 상태·전역 슬롯·해제 후 쿨타임은 그대로다.
- **F8**로 테스트 Loom의 납치를 강제로 해제할 수 있다. 정상 피해는 시작 3초 후부터 매초 2이며, 피격·넘어짐·사망 등의 정상 해제도 확인한다. 다른 생존자가 없으면 Loom은 기존 운반 로직에 따라 Leave로 전환할 수 있다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-RepoDev.ps1
```

1. 난이도 5, Loom·Robe 각각의 생성 요청, 스토커 동반 생성 로그를 확인한다. 두 스토커가 실제 보이는지, 본체가 재등장해도 동반 생성이 중복되지 않는지 확인한다.
2. Loom에게 발견된 뒤 장애물이 없는 4m 안으로 접근한다. 혼자여도 납치되어야 한다. 몸체는 등에 고정되고 카메라는 자유롭게 움직여야 한다.
3. 벽 뒤에서는 납치되지 않아야 한다. 납치 중 Loom Grab 차단, 주기 피해, F8 해제와 5초 재납치 쿨타임을 확인한다.
   손뼉 공격에 들어갈 거리까지 접근했을 때도 납치 조건을 만족하면 손뼉 공격보다 납치가 우선해야 한다. Loom의 공용 EnemyVision 유무와 무관하게 전용 시야 원점으로 벽 검사를 수행한다.
4. 스토커의 관찰 시 정지·미관찰 추적·기본 분노·난이도 3 이상 폭주도 확인한다. Robe 자체에는 납치를 부여하지 않는다.
5. 바닐라 참가자가 있을 때도 동반 생성·납치·해제의 결과가 일치하는지 확인한다. 자동 검사는 실제 게임 플레이를 대체하지 않는다.

일반 진행에는 여덟 Debug 시나리오를 모두 끄거나 Release를 사용한다. 이번 솔로 예외·F8 코드는 Release 빌드에서 제외한다.
