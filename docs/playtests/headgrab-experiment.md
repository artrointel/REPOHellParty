# Headgrab 사망자 위장 실험 — dev/test-headgrab

상태: **검증용 패치. 멀티플레이 성공 여부 미확인. main 반영 금지.**

## 목적과 범위

순정 Headgrab이 사망자의 머리를 장착했을 때, 살아 있는 원격 관찰자에게만 사망자 아바타의 `ReviveRPC`를 보내 외형 표시가 가능한지 확인한다. 실제 사망자와 호스트에는 보내지 않는다. 가짜 플레이어나 새 PhotonView를 생성하지 않는다.

이번 패치는 외형 표시, 위치 동기화, 피격 경로 관찰을 위한 것이다. Headgrab 외형을 숨기거나 음성을 녹음하지 않으며 피해를 자동 전달하지 않는다. 겹친 몬스터와 플레이어 콜라이더 중 어느 쪽에 공격이 들어가는지 확인하기 위해 몬스터도 그대로 표시한다.

## 실행

호스트 한 명, 사망할 순정 참가자 한 명, 살아 있을 순정 관찰자 한 명으로 **최소 3명**이 필요하다. 호스트 화면에는 위장 외형이 나타나지 않는 것이 의도된 동작이다. 관찰자 화면과 로그를 함께 기록한다.

일반 세이브와 분리된 테스트 세이브에서 실행한다. 수신자별 생사 상태를 의도적으로 다르게 만드는 실험이므로 정상 게임 플레이에 사용하지 않는다.

```powershell
# 빌드만: 설치나 게임 실행 없음
.\scripts\Build-Dev.ps1 -TestScenario Headgrab -NoRestore

# 게임 종료 후 빌드·프로필 배포·실행
.\scripts\Start-RepoDev.ps1 -TestScenario Headgrab
```

VS Code: `Tasks: Run Task` → `HellParty: Start Headgrab test`.

DLL: `src/HellParty/bin/Debug/Scenarios/Headgrab/netstandard2.1/HellParty.dll`.

기본 Debug와 Release에는 이 시나리오와 Harmony 관찰 패치가 포함되지 않는다. Release + Headgrab 옵션은 거부된다. 테스트에서도 난이도는 실제 진행도를 사용한다.

## 테스트 키 (호스트만)

| 키 | 동작 |
| --- | --- |
| F6 | 시작 준비: 호스트 근처에 샷건·수면총, 연결된 안전 바닥에 Headgrab 한 마리. 중복 몬스터 생성은 막는다. 배치 실패 시 트럭을 나와 재시도한다. |
| F7 | 테스트 Headgrab이 원격 사망자의 머리를 실제 장착한 상태에서 30초 외형 실험 시작. 현재 살아 있는 원격 관찰자들만 대상으로 한다. |
| F8 | 실험 중 관찰자에게만 초당 10회 `SpawnRPC`를 보내 Headgrab 몸체 위치·방향을 따라가도록 하는 실험 켜기/끄기. |
| F9 | 실험 종료. 관찰자들에게만 `PlayerDeathRPC`를 보내 다시 사망 처리를 요청한다. |

F7 전에 참가자가 정상적으로 사망하고 Headgrab이 순정 AI로 머리를 장착하도록 기다린다. 자동 사망이나 강제 머리 장착은 수행하지 않는다. 첫 외형 실험에서는 F8을 누르지 않는다.

## 순서와 판정

1. **표시:** F7 후 관찰자가 온전한 사망자 외형·색상을 보는지 기록. 사망 당사자가 관전을 유지하는지도 확인.
2. **머리 유지:** 관찰자에게 실행된 ReviveRPC의 `PlayerDeathHead.Reset()` 때문에 장착 머리나 Headgrab 연출이 깨지는지 기록. 이것도 실험 실패 신호다.
3. **추적:** F8을 켜서 위치 되돌아감·떨림·회전·발 위치를 확인. 이동 애니메이션 구현은 없으므로 걸음이 자연스럽다는 보장은 없다. 다시 F8을 꺼 차이를 비교한다.
4. **피격:** 샷건·근접·폭발을 구분해 관찰자가 공격한다. 호스트 로그의 player-hit RPC와 enemyHP 변화를 비교한다. RPC 도착은 유효 피해의 증거가 아니다. 사망자는 `deadSet` 때문에 순정 Hurt에서 피해가 거부될 가능성이 있으며, 이 경우 Headgrab으로 전달할 경로가 추가로 필요하다.
5. **종료:** F9, 30초 만료, Headgrab 사망·머리 해제, 실제 부활, 참가자 퇴장을 각각 확인한다. 실제 부활이 감지되면 추가 사망 RPC 없이 관찰을 중단한다.
6. 매 실험 후 로비로 복귀하고 다시 시작한다. 종료용 사망 RPC는 최선의 복구 시도이며, 순정 사망 연출·머리 위치까지 완전히 이전 상태로 복원함을 보장하지 않는다. 실제 부활과 종료가 네트워크상에서 교차하는 경우도 확인해야 한다.

로그 접두사: `TEST Headgrab`. 매초 호스트 기준 사망 플래그·플레이어 체력·몬스터 체력·위치를 출력한다. 관찰자 내부 상태는 호스트에서 확인할 수 없으므로 화면 확인이 필수다.

## 일반 빌드로 복귀

게임 종료 후 `Start-RepoDev.ps1`을 **옵션 없이** 실행하면 일반 Debug로 다시 배포된다. `-NoBuild`는 기존 실험 DLL을 그대로 사용하므로 복귀 용도로 쓰지 않는다. 브랜치 전환만으로 설치된 DLL이 교체되지는 않는다.

실험 변경은 이 브랜치에서만 관리한다. 성공 시 검증된 코드만 main으로 별도 반영하며, 현재 실험 키·관찰 로그·수신자별 부활 패치를 그대로 출시하지 않는다.
