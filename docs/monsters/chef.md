# Chef

## 변장(미믹)

- **해금:** 난이도 1(stage1). 이후 단계에서도 유지하며 0단계는 순정 그대로다.
- **탐색:** 배회·대기 중 1초마다 재시도한다. 본체 반경 20m 이내의 살아 있는 플레이어에게 ray를 쏘아 장애물이 없으면 즉시 변장한다. 방향 제한은 없으며 벽 너머의 플레이어로는 발동하지 않는다.
- **인지 조건 예외:** 기존 공격 대상이 없어도 탐색한다. 플레이어 발견 시 순정 추격을 시작하는 대신 변장한다.
- **변장:** 순정 Frog 수집품을 본체 위치 근처 바닥에 생성하고, 기존 Chef 본체는 순정 디스폰 동기화로 숨긴다. 새로운 Chef를 만드는 방식이 아니다. 변장 중에는 본체의 자동 재등장을 차단한다. Frog 위치를 기준으로 1초마다 반경 20m와 장애물 없는 ray를 다시 검사한다. 보이는 살아 있는 플레이어가 한 명도 없는 상태가 연속 5초 유지되면 Frog를 조용히 제거하고, 기존 체력을 유지한 Chef가 공격 대상 없이 배회로 복귀한다. 20m 안에 있어도 모두 벽에 가려진 상태가 연속 5초 유지되면 해제한다. 그 전에 한 명이라도 다시 감지되면 시야 상실 타이머를 초기화하고 변장을 유지한다. 시간은 첫 시야 상실 감지부터 계산하며 기존 1초 검사 간격을 유지한다. 이 해제는 처치가 아니므로 코어를 생성하지 않는다.
- **내구성·드론:** 변장 Frog는 순정 Frog의 내구·파괴 판정을 사용한다. 무기뿐 아니라 주변 물건·지형·몬스터 등의 환경 요인으로 실제 파괴되어도 Chef 처치로 판정하고 그 위치 근처에 순정 코어를 드랍한다. 공격자 식별을 보상 조건으로 요구하지 않는다. 드론은 후보 선택과 부착 메시지 송신 직전에 변장 Frog를 제외한다. 노움도 공격할 가치품 후보에서 변장 Frog를 제외하며, 다른 순정 가치품이나 플레이어는 기존 규칙대로 선택한다. 일반 Frog에는 적용하지 않는다.
- **변장 해제:** 실제 Grab 수락 후 순정 Grab 처리가 끝나는 다음 프레임에 모든 잡은 플레이어에게 순정 해제 메시지를 보낸다. Frog를 조용히 제거하고 기존 Chef를 유효한 바닥에 복귀시킨다. 복귀 직후 0.5초 동안 재Grab을 제한해 기존 잡기가 이어지지 않게 한다. 잡은 플레이어를 대상으로 순정 Notice → MoveToPlayer → Tell → Tumble을 진행하여 발견·조준·접근·공격 예고·점프 공격을 생략하지 않는다. Frog에서 받은 피해까지 반영한 공유 체력으로 복귀한다.
- **재변장 금지·공격 종료:** Grab으로 변장을 해제한 Chef는 현재 공격 대상이 살아 있고 추격이 유지되는 동안 다시 변장하지 않는다. 공격 후 Idle·자세 복구나 순간적인 순정 시야 판정 공백은 타깃 해제로 보지 않으며, 같은 대상을 다시 추격한다. 대상이 사망·비활성화되거나 순정 MoveToPlayer의 추격 타이머·이동이 종료되면 타깃을 해제한다. 순정 OnVision이 추격 타이머를 갱신하는 동작은 유지한다. 20m와 별도 ray 검사는 변장 시작·유지·해제에만 사용하며, 추격 종료를 막거나 연장하는 데 사용하지 않는다. 구르기 중이었다면 순정 자세·내비게이션 복구를 먼저 수행한다. 다시 배회·대기 상태가 되면 1초 재시도 간격에 따라 새 플레이어를 탐색한다.
- **공유 체력·내구도:** 본체 체력 비율과 Frog의 남은 유효 내구도 비율을 공유한다. 순정 가치품은 원래 가치의 15% 아래에서 파괴되므로, 가치 15~100% 구간을 내구도 0~100%로 환산한다. 본체 체력 50%라면 Frog의 유효 내구도도 50%(원래 가치의 약 57.5%)로 시작한다. Frog의 피해·회복도 같은 비율로 본체에 반영하며, Grab 해제·시야 상실 해제·재변장으로 초기화되지 않는다. 본체의 정수 체력과 가치의 표시 단위로 인한 반올림은 내부 비율과 분리하여 반복 변신으로 체력이 회복되지 않게 한다. 순정 재스폰에 따른 새 생명은 새 체력으로 초기화한다.
- **보상:** Frog의 순정 가치는 내구·파괴 판정에 사용하되 라운드의 획득 가능 금액에는 더하지 않는다. Grab 시 없어져 추가 수집 보상으로 남지 않는다. 변장 Frog 파괴는 본체의 순정 사망·코어 생성 경로를 사용한다. 중복 파괴 콜백은 한 번만 처리하며, Grab 처리 중 파괴되면 공격 복귀를 취소하고 처치로 처리한다. 일반 본체 처치의 코어 규칙은 유지한다.
- **정리:** 사망·스테이지 종료 시 남은 변장 Frog를 정리한다.

## 구현과 확인

Chef의 순정 구현은 `EnemyTumbler`다. 호스트가 탐색·타깃·변장을 판정하고, 순정 몬스터 스폰/디스폰·타깃/상태 RPC와 네트워크 가치품만 이용한다. 참가자 전용 코드나 새 RPC를 요구하지 않는다. 드론은 호스트의 순정 대상 선택·부착 단계에서 변장 Frog를 제외한다. 노움은 순정 가치품 후보를 조회한 직후 변장 Frog를 걸러내고 나머지 선택 로직을 그대로 수행한다.

자동 검사는 해금, 20m 경계, 1초 재시도, 변장 중 시야 재검사·연속 5초 시야 상실 경계·재발견 시 타이머 초기화·시야 상실 후 배회 복귀·Grab과의 경합, 변장/해제/공격 전환, 중복 Grab·파괴 처리 방지, 파괴와 Grab의 경합 및 설치된 게임의 패치 지점을 확인한다. 공격 후 타깃 유지·재변장 방지, 순정 추격 종료와 변장 감지의 분리, 체력·내구 비율과 반복 변신 시 피해 유지도 검사한다. 실제 이동·공격·노움 대상 선정·드론 부착과 바닐라 참가자 화면은 [Chef 플레이테스트](../chef-playtest.md)로 확인한다.

Upscream 전용 Debug 시나리오는 Chef와 공유하는 변장 로직을 확인할 수 있다. 실제 활성 시나리오는 [개발 환경](../development.md#debug와-release)의 프로필 설정을 따른다. Chef의 단계별 검증은 실제 진행도를 사용하는 Release 또는 모든 시나리오를 끈 Debug의 자연 생성 개체로 수행한다.
