# Birthday Boy

## 특수 능력: 풍선강화1 / 풍선강화2 / 풍선강화3

호스트만 설치하고 바닐라 참가자와 함께 플레이한다. 순정 풍선을 이동시키는 대신 근접 감지 파열과 Gnome 생성을 사용한다.

## 단계별 효과

- 0단계(stage1~3): 순정 상태 그대로 진행한다.
- 1단계(stage4~6) — 풍선강화1: 플레이어가 풍선 반경 3m 안에 연속 3초 머무르면 자동 파열한다. 자동 파열 또는 플레이어 접촉·외부 물리 충격으로 터질 때, 풍선 반경 10m 안에 플레이어가 있으면 Gnome 1마리가 나타난다. 자동 파열은 본체 어그로를 유발하지 않는다.
- 2단계(stage7~9) — 풍선강화2: 이전 효과에 더해 자동 파열 시 감지한 플레이어를 본체 공격 대상으로 지정한다. 본체 사망 시 가장 최근에 생성한 잔존 풍선 최대 3개에서 Eyeball을 생성한다.
- 3~5단계(stage10 이상) — 풍선강화3: 이전 효과에 더해 본체가 피해를 받으면 본체 반경 10m 안의 모든 풍선이 일시에 터지며 각각 Gnome 1마리를 생성한다.

## 풍선강화1: 근접 감지와 일반 파열

- 순정 배치 애니메이션이 끝나고 접촉 콜라이더가 활성화된 풍선부터 각자 감지한다.
- 풍선의 실제 `moveTransform.position`과 살아 있고 활성화된 플레이어의 `transform.position` 사이 3차원 직선 거리를 사용한다. 정확히 3m·10m인 경계도 포함한다. 시야나 장애물 검사는 요구하지 않는다.
- 반경 3m 안에 플레이어가 1명 이상 있는 상태가 연속 3초 유지되면 자동 파열한다. 모두 벗어나면 시간을 초기화한다. 안에 남은 플레이어가 교체되는 것만으로 초기화하지 않는다. 자동 파열 대상으로 가장 가까운 플레이어를 선택한다.
- 일반 파열은 플레이어가 직접 터뜨린 경우와 플레이어가 직접 조작하지 않은 물체의 물리 충격으로 터진 경우를 포함한다. 실제 파열 순간 반경 10m 내에 살아 있고 활성화된 플레이어가 1명 이상 있으면 Gnome 1마리를 생성한다. 없으면 Gnome을 생성하지 않는다. 자동 파열에도 이 규칙을 적용한다.
- Gnome은 가까운 플레이어를 대상으로 순정 AI를 사용한다. 본체의 기존 타깃 유무는 생성 조건이 아니다.
- 자동 파열은 [인지 상태 조건](../metadata/recognition-state.md)의 예외다. 본체가 플레이어 타깃을 보유하지 않아도 작동하지만, 본체가 사망·디스폰 중이면 근접 체류 시간 누적과 자동 파열을 중단한다.
- 풍선강화1의 자동 파열은 순정 수동 제거 경로를 이용해 본체 타깃·분노 상태를 변경하지 않는다. 기존 어그로를 해제하지도 않는다.
- 플레이어 접촉·외부 충격으로 인한 일반 파열의 본체 어그로 처리는 순정 로직을 유지한다.
- 순정의 오래된 풍선 교체나 맵 정리로 제거되는 경우에는 Gnome을 생성하지 않는다.

## 풍선강화2: 본체 어그로와 사망 보상

- 자동 파열 시 Gnome 생성과 함께 감지한 플레이어를 순정 `UpdatePlayerTarget`으로 본체 공격 대상으로 지정한다. 순정 플레이어 파열의 분노 처리 경로로 추격·공격을 시작한다.
- 본체가 사망하면 순정처럼 생성했던 모든 잔존 풍선이 터진다. 이 사망 파열에서는 Gnome 대신 가장 최근에 생성한 잔존 풍선 최대 3개에서 각각 Eyeball 1개를 생성한다.
- 남은 풍선이 3개보다 적으면 남은 수만큼 지급한다. 나머지 오래된 풍선은 보상을 생성하지 않는다. 플레이어가 근처에 없거나 본체 타깃이 없어도 사망 보상을 지급한다.
- 생성 순서는 소유 Birthday Boy별로 관리한다. 이미 파열된 풍선은 사망 보상 후보에서 제외한다. 동일 풍선에서 Gnome·Eyeball이 중복 생성되지 않는다.

## 풍선강화3: 피격 시 노움 지원

- 호스트의 순정 `EnemyHealth.Hurt` 처리 전후 체력을 비교한다. 본체가 스폰된 상태에서 실제로 체력이 감소했고 생존한 경우마다 발동한다. 피해가 차단되거나 저항·반올림으로 체력이 줄지 않은 경우에는 발동하지 않는다. 별도 쿨타임은 없다.
- 중심은 피격 본체의 실제 물리 몸체 위치다. 풍선의 실제 위치까지 3차원 직선 거리 10m 이내인 모든 풍선을 같은 피격 처리에서 순정 파열 RPC로 터뜨린다. 다른 살아 있는 Birthday Boy가 소유한 풍선도 이 범위에 있으면 포함한다.
- 각 풍선에서 Gnome 1마리를 생성한다. 이 피격 지원 파열에는 일반 파열의 주변 플레이어 조건을 추가하지 않는다. 피격 지원 발동 시점에 본체가 보유한 살아 있고 활성화된 공격 대상을 저장하고, 이 파열로 생성하는 모든 Gnome의 공격 대상으로 우선 지정한다. 풍선에 더 가까운 다른 플레이어나 다른 소유 본체의 타깃이 있어도 피격 본체의 대상을 공유한다. 유효한 본체 타깃이 없으면 각 풍선 주변 10m 내 가장 가까운 플레이어를 선택한다.
- 공유 대상은 순정 Gnome 초기화가 끝난 뒤 적용한다. 이미 다른 대상을 공격 중인 경우에도 공유 대상을 반영하고, 주변 가치품 대신 해당 플레이어를 공격하는 순정 상태로 전환한다. 스폰 대기 중 대상이 사망하거나 비활성화되면 공유 대상 지정을 생략한다. 이후 행동은 순정 AI를 따른다.
- 순정 Gnome Director는 무리 전체의 공격 대상을 공유하므로, 이 지정은 기존에 있던 Gnome들의 공격 대상에도 영향을 줄 수 있다.
- 피격 지원 파열로 다른 소유 본체의 타깃이나 분노 상태를 강제로 변경하지 않는다. 피격 본체의 반응은 순정 피격 AI가 처리한다.
- **치명타는 사망 처리를 우선한다.** 체력이 0이 되는 공격에는 피격 지원 파열을 실행하지 않고, 해당 본체의 순정 전체 풍선 파열과 최근 최대 3개의 Eyeball 보상 규칙을 적용한다. 다른 본체의 풍선은 이 치명타로 파열시키지 않는다.

## 구현과 검증

- 호스트가 시간·거리·피격·보상 순서를 판정하고 순정 `RemoveBalloonRPC`·`PopAllBalloonsRPC`로 참가자에게 파열을 전달한다. 커스텀 RPC·프리팹은 추가하지 않는다.
- Gnome은 순정 `Enemies/Enemy - Gnome`을 사용한다. 필요하면 순정 Gnome Director도 네트워크 생성한다. 풍선 파열 위치에서 가까운 NavMesh 지점에 순정 초기화·등록·스폰 절차를 거쳐 나타난다.
- 숨겨진 대기 위치에서 이동한 개체는 최초 스폰 활성화 직후 순정 `EnemyNavMeshAgent.Warp(position, true)`로 NavMesh에 다시 등록한다. 단순 좌표 이동에서 순정 Warp의 근거리 생략 조건에 걸려 이동 경로를 받지 못하는 문제를 방지한다. 이후 이동·추격·공격은 순정 AI가 처리하며 매 프레임 위치를 강제하지 않는다.
- Eyeball은 순정 `Valuables/01 Tiny/Valuable Wizard Eye Ball`을 사용한다.
- 현재 Debug 자동 생성 대상은 [Bella](../bella-playtest.md)다. Birthday Boy의 자연 생성 개체도 능력이 적용되며, Release는 실제 스테이지 난이도를 따른다.
- 실제 게임 확인은 [Birthday Boy 플레이테스트](../birthday-boy-playtest.md)를 따른다. 자동 검증은 Unity 플레이와 바닐라 참가자 검증을 대체하지 않는다.

단계별 한 줄 요약은 [특수 능력 기획표](../monster-abilities.md)에서 관리한다.
