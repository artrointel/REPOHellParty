# Peeper

0단계는 순정 상태 그대로 진행한다. 호스트가 순정 네트워크 몬스터를 생성하고 순정 AI로 공격 대상을 전달한다.

호스트만 모드를 설치하고 바닐라 참가자와 완벽하게 호환되는 능력만 기획한다.

## 1단계(stage1): 노움소환

- Peeper의 공격으로 플레이어 체력이 실제 감소하는 유효 타격마다 Peeper 위치에 Gnome 1마리를 소환한다. 무적·회피 등으로 피해가 없는 접촉은 소환하지 않는다.
- Gnome과 Banger를 합쳐 Peeper 개체별 누적 최대 10마리를 소환한다. 처치·디스폰되어도 누적 횟수를 반환하지 않으며, Peeper의 순정 재등장으로 초기화하지 않는다.
- 소환 시점의 Peeper 공격 대상을 보관하여, 소환된 Gnome이 스폰을 완료하면 해당 플레이어를 공격 대상으로 지정한다.

## 2단계(stage4): 뱅거소환

- 노움소환을 유지하면서 매 유효 타격마다 독립적인 30% 확률로 Banger 1마리를 추가 소환한다. 노움 대신 선택하는 방식이 아니다.
- Banger도 Peeper 위치에 소환하며, 스폰 완료 후 해당 타격 시 Peeper의 공격 대상이었던 플레이어를 대상으로 삼는다.
- Banger도 공용 누적 10마리 한도를 1개 소비한다. 자리가 2개 이상이고 확률이 성공하면 한 타격에서 Gnome·Banger 각 1마리, 총 2마리가 생성된다. 남은 자리가 1개라면 Gnome이 우선하며 Banger는 추가하지 않는다. 한도를 모두 사용하면 두 소환을 모두 중단한다.

## 공통 규칙

- 한 번의 유효 타격을 중복 콜백·네트워크 메시지로 여러 번 처리하지 않는다.
- 별도의 무코어·수명 제한은 지정하지 않았으므로 순정 소환 몬스터 규칙을 따른다.
- Peeper가 천장에 있으므로 본체 위치 아래의 지형과 NavMesh를 찾아 그 바닥에 소환한다. 스폰 후 순정 내비게이션을 강제로 바인딩한다. 유효 위치를 찾거나 네트워크 개체를 생성하지 못하면 소환 횟수를 소비하지 않고 오류를 남긴다.
- 공격 대상과 본체 위치는 피해 요청 시점에 보관한다. 타깃이 스폰 완료 전에 죽거나 비활성화되면 죽은 플레이어를 강제 지정하지 않고 순정 AI에 맡긴다.
- Gnome과 Banger는 각각 순정 전역 그룹 Director를 공유한다. 초기 공격 대상은 그 Director에 전달하므로 기존 같은 종류의 몬스터도 함께 대상이 바뀔 수 있으며, 서로 다른 Peeper의 소환이 겹치면 최근 지정 대상이 그룹에 적용된다. 개체별 독립 타깃을 보장하는 새 참가자 코드는 추가하지 않는다.

## 유효 타격과 네트워크

- 순정 Peeper(`EnemyCeilingEye`)는 공격 대상을 정한 뒤 `PlayerHealth.HurtOther`에 피해 2와 본체의 적 인덱스를 전달한다. 이 인덱스로 Peeper의 피해 요청만 추적한다. 순정 피해량·공격 주기는 변경하지 않는다.
- 호스트 자신은 해당 호출 전후의 실제 체력 감소를 확인한다. 바닐라 참가자는 피해 요청 후 2초 안에 도착한 인증된 체력 감소 또는 생존→사망 메시지를 확인한다. 한 번 확인한 요청은 제거하며, 하나의 체력 감소를 여러 Peeper에게 중복 반영하지 않도록 가장 오래된 요청 하나만 처리한다. 치명타도 유효 타격이다.
- 순정 체력 메시지는 공격자 정보를 포함하지 않는다. 확인 대기 중 같은 플레이어가 다른 피해를 입거나 여러 Peeper의 타격이 겹치면 정확한 공격자·타격 시점을 구분하는 데 제한이 있다. 순정 메시지와 프리팹만 사용하며 실제 멀티플레이 검증은 별도로 필요하다.
- 구현은 Debug/Release에 포함된다. Peeper 전용 자동 생성은 없으며, Debug와 Release 모두 [실제 진행도](../metadata/difficulty.md)를 사용한다. 실제 확인 항목은 [Peeper 플레이테스트](../peeper-playtest.md)를 따른다. [난이도별 기획표](../monster-abilities.md)에는 단계별 신규 효과만 한 줄로 기록한다.
