# 몬스터 웨이브

글로벌 이벤트이며 몬스터의 타깃 보유·인지 상태와 관계없이 가치품 파괴를 계기로 발동한다. 난이도 1(stage1)부터 해금하고 난이도 2~5에서도 유지한다. 스테이지에서 몬스터를 소환하는 웨이브는 동시에 1개이며, 교체 후보의 음악 예고는 별도로 최대 1개 존재할 수 있다.

## 발동 조건

- 수집 가능한 가치품 물건이 실제로 파괴되었을 때 파괴 위치를 새 이벤트 중심으로 삼는다. 단순 가격 감소·이동·Grab은 발동 조건이 아니다.
- 몬스터 코어 구슬(순정 `EnemyValuable`)은 발동 대상 수집품에서 제외한다. 구슬이 파괴되어도 웨이브를 발생시키거나 아래의 3초 제한을 소비하지 않는다.
- 파괴에 따른 신규 웨이브 조건 검사는 스테이지 전체에서 3초에 한 번만 수행한다. 첫 검사 시도부터 3초가 지나기 전의 후속 파괴는 플레이어 검색·사각지대 계산·생성 로직에 진입하지 않는다. 첫 검사가 시작 조건 미충족으로 실패해도 3초 제한을 적용하며, 기존 웨이브는 유지한다. 스킵된 파괴는 예약하지 않고 제한 시간도 연장하지 않는다. 정확히 3초가 지난 뒤부터 다시 검사할 수 있다.
- 진행 중인 웨이브 또는 음악 예고 중심 반경 20m 이내(경계 포함)에서 발생한 가치품 파괴는 재발동 조건에서 제외한다. 영역 밖 파괴만 새 웨이브를 시도하며, 영역 밖에서도 시작 조건을 만족해야 교체한다.
- 새 중심 반경 20m 이내에 살아 있는 플레이어가 1명 이상 있어야 한다.
- 시작 시점에 같은 반경 안에서 모든 플레이어에게 보이지 않으며 몬스터를 실제로 생성할 수 있는 사각지대가 최소 1곳 있어야 한다. 가시성 외에 바닥·공간 등 스폰 가능 조건도 만족해야 한다. 반경 안의 플레이어만이 아니라 모든 살아 있는 플레이어의 관찰 여부를 고려한다.
- 두 조건 중 하나라도 만족하지 못하면 새 이벤트는 발생하지 않는다. **이때 진행 중이던 기존 웨이브는 취소하지 않는다.**
- 위 사전 조건을 만족하면 새 Gramophone을 만들고 3초간 음악 예고를 시작한다. 이 시점에는 기존 웨이브를 종료하지 않는다.
- 새 Gramophone 생성 3초 후, 몬스터 스폰을 시작하기 직전에 새 중심 반경 20m 안에 살아 있는 **서 있는 자세의 플레이어가 1명 이상** 있어야 한다. 서 있기·걷기·달리기는 모두 해당하며 이동 속도 자체는 조건이 아니다. 웅크리기·기어가기·래그돌 상태는 제외한다. 이는 자세 판정이며 장애물 뒤에서 서 있는 플레이어도 해당한다.
- 예고 종료 시 모두 숨은 자세이거나 반경 안에 유효한 플레이어가 없으면, 새 이벤트를 즉시 취소하고 새 Gramophone을 제거한다. 몬스터는 한 마리도 생성하지 않는다. 이후 다시 일어서도 취소된 이벤트를 되살리지 않는다.
- 최종 자세 조건까지 통과한 경우에만 기존 웨이브를 종료·정리하고 새 이벤트로 교체한다. **예고가 취소되면 기존 웨이브는 원래 종료 시각까지 유지한다.** 기존 몬스터·Gramophone·미처리 소환 요청을 새 이벤트로 넘기지 않는다. 반경 밖 파괴로 예고 후보가 다시 교체되면 이전 후보의 Gramophone만 정리하고 새 후보의 3초를 센다.

## 이벤트 시작과 고정 Gramophone

- 파괴 위치에 순정 **Gramophone**를 생성·고정하고 해당 아이템의 음악을 재생한다. 이벤트 중심은 시작 위치로 고정한다.
- 음악 오브젝트 생성 후 첫 3초는 회피를 위한 예고 시간이며 몬스터를 소환하지 않는다. 플레이어는 이 시간 안에 웅크리거나 기어가는 자세로 숨어 새 웨이브를 회피할 수 있다. 자세 검사는 3초 종료 시점에 한 번 수행한다.
- 이벤트용 Gramophone은 수집·이동할 수 없고 파괴되지 않는다. Grab 시도는 강제로 해제하며 시도한 플레이어에게 피해 10을 준다. 같은 시도의 중복 메시지로 피해를 여러 번 주지 않는다.
- 소환이 시작된 이벤트가 종료되거나 새 이벤트로 교체되면 Gramophone을 순정 파괴 효과·사운드와 함께 파괴한다. 플레이어 공격에는 계속 파괴되지 않는다. 3초 예고가 회피로 취소되거나 예고 후보가 교체된 경우에는 조용히 제거한다. 이벤트용 Gramophone의 생성·파괴·제거 및 내부 정리로 또 다른 웨이브를 발생시키지 않는다.

## 소환 동작

- Gramophone 생성 3초 후 최종 자세 검사를 통과하면 Rugrat·Upscream·Headgrab을 각 1마리씩 소환 요청한다. 실제 배치도 반드시 중심 20m 안의 사각지대에서 수행한다.
- 초기 3종의 요청 1초 후부터 매 1초마다 무작위 사각지대를 계산하여 **Gnome 2마리**를 소환 요청한다. Gramophone 생성 기준 요청 시점은 4~19초이며 최대 32마리다. 20초에는 새로 소환하지 않는다. 두 개체 모두 각자의 사각지대 검사를 통과해야 한다. 시작 때 검사한 자리라고 이후에도 보이지 않는 것으로 간주하지 않는다.
- 시작에 필요한 최소 사각지대 1곳이 있어도, 초기 3종 모두를 동시에 배치할 수 있을 필요는 없다. 배치 가능한 공간이 부족하면 나머지는 지연 처리한다. 이미 사용 중이거나 플레이어가 보고 있는 지점에 억지로 겹쳐 소환하지 않는다.
- 공간 검사는 각 몬스터의 순정 NavMeshAgent 높이·반경을 사용한다. 큰 몬스터가 배치되지 못해도 요청을 뒤로 돌려 작은 Gnome의 소환을 계속 시도한다. 한 번의 처리에서는 최대 4개 요청을 검사하고 1초 간격으로 재시도한다.
- 스폰 위치는 모든 살아 있는 플레이어로부터 **3m 초과**로 떨어져야 한다. 그 외의 추가 안전거리는 두지 않으므로, 아무도 보지 않고 공간·이동 경로 조건을 만족하면 플레이어 바로 뒤의 가까운 위치도 허용한다.
- 기존에 검증했던 위치를 먼저 재사용한다. 중심 위치와 몬스터의 에이전트 종류·이동 영역·몸체 크기별로 최대 16개를 캐시하고, 현재 가장 가까운 플레이어까지의 거리순으로 재검증한다. 플레이어 시야·3m 거리·충돌·다른 소환수의 점유·NavMesh와 이동 경로를 다시 통과한 경우에만 사용한다.
- 캐시에서 쓸 수 있는 위치가 없으면 NavMesh에서 최대 240회 무작위 후보를 추출한다. 반경 안 후보를 **가장 가까운 살아 있는 플레이어까지의 거리순**으로 정렬하고 가까운 후보부터 검사한다. 첫 유효 위치를 찾으면 나머지 검사를 중단한다. 서로 다른 240개 지점을 보장하거나 반경 안의 절대 최근접 지점을 찾는 방식은 아니다.
- 전체 후보 탐색에 실패한 중심·에이전트 조건은 1초 동안 전체 탐색을 다시 수행하지 않는다. 같은 주기에 같은 조건의 요청이 여러 개 있어도 실패한 240회 탐색을 중복하지 않는다. 이 대기 중에도 캐시 위치가 다시 유효해졌다면 재검증 후 사용할 수 있다. 실제 등장 직전의 위치 검사가 실패한 경우에도 1초 뒤 재시도한다.
- NavMesh 전체 삼각형 정보는 웨이브 시스템이 준비되는 스테이지 시작에 한 번 조회하고 캐시한다. 각 이벤트 중심에 해당하는 삼각형 목록도 캐시하며, 진행 중인 중심과 새 예고 중심을 번갈아 검사할 때 재구축하지 않는다. 스테이지가 바뀌면 위치 캐시와 NavMesh 정보도 초기화한다.
- 아직 등장하지 않고 초기화 중인 소환수의 예약 위치도 점유된 것으로 본다. 자기 자신의 예약·콜라이더는 재검증에서 제외하되, 다른 개체와는 겹쳐 생성하지 않는다.
- 소환된 몬스터는 각자의 스폰 위치를 기준으로 가장 가까운 살아 있는 플레이어를 초기 공격 대상으로 지정한다.
- 사각지대가 이동 불가능한 고립된 NavMesh 섬이 되지 않도록, 해당 몬스터의 에이전트 종류·이동 가능 영역으로 최근접 플레이어까지 완전한 이동 경로가 이어지는 위치만 허용한다. 실제 스폰 직전에도 재검사하고, 스폰 후 이동 에이전트를 명시적으로 활성화·연결한다.
- 웨이브 소환수는 사전 검사한 사각지대의 유효 NavMesh 위치에서 초기화한다. 맵 밖 대기 위치에 NavMeshAgent를 먼저 생성했다가 옮기면서 생기던 초기 연결 경고를 피한다. 순정 등록·초기화·등장 흐름을 유지하고 실제 등장 전에는 사각지대를 다시 검사한다. 자기 자신의 초기 위치는 다른 몬스터의 점유로 취급하지 않는다.
- 소환 지연 때문에 이벤트 시간을 연장하지 않는다. 종료 시 아직 처리하지 못한 소환 요청은 취소한다.

## 지속과 종료

- 이벤트 지속시간은 **Gramophone 생성 시점부터 20초**다. 첫 3초 예고도 포함하며 몬스터 소환 구간은 3~20초다. 새 이벤트도 자신의 Gramophone 생성 시점부터 계산한다. 자세 검사나 스폰 지연으로 종료 시각을 연장하지 않는다.
- 20초가 지나거나 유효한 새 이벤트로 교체되면, 해당 이벤트로 생성한 몬스터만 디스폰 처리하고 Gramophone을 순정 연출로 파괴한다. 기존 순정 몬스터나 다른 시스템의 소환수는 종료 대상으로 삼지 않는다.
- 최종 자세 검사를 통과해 소환이 시작된 뒤에는 모두 숨거나 반경 밖으로 나가는 것만으로 즉시 종료하지 않는다. 3초 시점의 반경 내 자세 판정은 스폰 시작 조건이다.
- 소환 몬스터의 보상·별도 능력·추가 이벤트 강화는 이번 조건·동작 정의에 포함하지 않는다.

## 세부 판정 검토

순정 Gramophone 프리팹은 `TrapGramophone`을 사용한다. `Trap.TrapStartRPC`로 전체 참가자에게 활성화를 전달하면 Grab 여부와 관계없이 음악과 회전 애니메이션이 실행된다. 재생 위치 선택도 순정 `SyncedEventRandom`으로 동기화된다. Museum Boombox의 Grab 중 재생 제약을 피하기 위해 Gramophone으로 교체한다.

Gramophone의 종료 이벤트는 `SyncedEventTimer`가 관리하며 호스트만 시간을 계산하고 종료 RPC를 보낸다. 이벤트용 개체의 호스트 타이머를 25초로 두고 웨이브가 20초에 개체를 제거하여, 순정 참가자에게도 이벤트 종료까지 재생이 유지되도록 한다. 재생 시작에는 순정 시동 연출이 포함된다.

Gnome은 순정에서 그룹 Director가 타깃을 공유한다. 이벤트 Gnome은 순정 AI를 실행하는 동안에만 개체별 타깃을 적용하고 즉시 그룹 상태를 복원한다. 일반 Gnome·Peeper·Birthday Boy의 그룹 타깃을 덮어쓰지 않는다.

사각지대는 시작 시점에만 검사하는 조건과 실제 매 소환 때 다시 검사하는 조건을 모두 적용한다. 바닐라 참가자의 정확한 화면 FOV·비율을 호스트가 받지 못하므로, 구현에서는 보이는 위치에 나타나지 않도록 로컬 화면의 여유 있는 시야 범위와, 원격 플레이어에 대해서는 전송된 카메라 방향과 넓은 170°×140° 시야 범위를 사용하고, 범위 안에 든 몸체 표본점에는 장애물 차폐를 검사한다. 시야 뒤쪽의 공간도 후보가 될 수 있다. 후보가 부족하면 소환을 지연한다.

자세 판정은 순정 `PlayerAvatar.isCrouching`, `isCrawling`, `isTumbling`을 사용한다. 웅크림·기어가기 상태는 순정 `OnPhotonSerializeView`로 전송되므로 바닐라 참가자도 동일한 회피 조건을 사용할 수 있다. 원격 자세는 호스트가 마지막으로 받은 상태를 기준으로 판정한다.

## 실제 테스트

1. 음악 오브젝트 생성 후 3초 전에는 초기 3종을 포함해 아무 몬스터도 생성되지 않는지 확인한다.
2. 반경 안의 전원이 3초 이내에 웅크리거나 기어가면 음악 오브젝트가 제거되고 소환이 취소되는지 확인한다. 전원이 영역 밖으로 벗어난 경우도 확인한다.
3. 반경 안에 한 명이라도 서 있거나 걷거나 달리면 3초 시점부터 초기 3종이 생성되고, 4초부터 노움이 초당 2마리씩 요청되는지 확인한다. 공간 부족에 따른 소환 지연은 허용한다.
4. 소환이 시작된 뒤 모두 숨어도 웨이브가 유지되며, 생성 기준 20초에 몬스터와 음악 오브젝트를 정리하는지 확인한다.
5. 기존 웨이브 영역 밖에서 새 예고를 만들고 회피하면 기존 웨이브가 유지되는지, 회피하지 않으면 교체되는지 확인한다.
6. 바닐라 참가자의 웅크림·기어가기에도 회피 판정이 적용되는지 확인한다.
7. 중심으로부터 20m 안에서만 생성되고, 모든 살아 있는 플레이어로부터 3m 초과 거리를 지키는지 확인한다. 시야에 잡히지 않는 플레이어 뒤쪽의 가까운 위치도 생성 가능한지 확인한다.
8. 캐시 위치를 바라보거나 다른 물건으로 막으면 재사용하지 않는지 확인하고, 다시 비워지면 재사용 가능한지 확인한다. 공간 부족 시 재시도 간격은 1초이며, 다른 크기의 몬스터가 작은 몬스터의 캐시를 무조건 통과하지 않는지도 확인한다.
9. 웨이브 종료·교체 시 Gramophone의 순정 파괴 연출이 호스트와 바닐라 참가자 모두에게 보이는지, 해당 파괴로 새 이벤트가 발생하지 않는지 확인한다. 예고 취소 시에는 파괴 연출 없이 제거되어야 한다.
10. 같은 스테이지에서 웨이브를 여러 번 끝내고 다시 시작한다. 퇴장한 개체가 새 웨이브에서 정상 체력·등장 연출·새 타깃으로 나타나고, 이전 웨이브 종료가 새 생명을 퇴장시키지 않아야 한다. ID 점유는 동시 소환 최고치에 따라 증가할 수 있으나 매 웨이브마다 새 소환 수만큼 계속 늘어나서는 안 된다. 청소부 부화와 섞어도 각각의 수명·타깃·종료 규칙이 유지되어야 한다.

종료 시 순정 디스폰 상태와 애니메이션을 사용하며, 웨이브 소환 개체가 이후 순정 재스폰 타이머로 다시 나타나지 않도록 차단한다. 난이도·타이머 단위 테스트와 순정 코드 계약 검사를 수행하며, 실제 게임의 사운드·멀티플레이 동작 확인은 별도로 필요하다.

퇴장이 완료되어 숨겨진 웨이브 소환수는 2초간 기존 통신을 기다린 뒤 같은 스테이지·같은 프리팹의 다음 웨이브 소환에 재사용한다. 순정 몬스터나 청소부 소환수와는 풀을 공유하지 않는다. 재사용 시 타깃·웨이브 소속·퇴장 상태·코어 드랍 횟수를 새 생명으로 초기화하고, 순정 스폰 RPC로 체력과 등장 연출을 복구한다. 종료된 웨이브의 소환수가 자발적으로 재등장하는 것은 허용하지 않는다.

새 인스턴스가 필요하면 해당 프리팹의 모든 PhotonView 수를 검사하고 순정 생성용 ID 32개를 남긴다. 여유가 부족하면 3초 후 다시 시도하며 이벤트 종료 시 미생성 요청은 버린다. 이때 같은 용량 경고는 최대 10초에 한 번 남긴다. 재사용 가능한 개체는 새 ID 없이 등장할 수 있다. 무제한 동시 소환이나 다른 모드의 ID 점유까지 해결하는 기능은 아니다.
