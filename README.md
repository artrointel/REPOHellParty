# REPO Hell

R.E.P.O.에 누적 난이도와 몬스터 특수 능력을 추가하는 호스트 전용 모드.

## 핵심 제약

- 호스트만 모드를 설치한다.
- 모드를 설치하지 않은 바닐라 플레이어가 같은 방에 정상적으로 참가하고 플레이할 수 있어야 한다.
- 참가자에게 별도 플러그인, 에셋, 설정 변경을 요구하지 않는다.
- 호환성이 검증되지 않은 능력은 기본 배포에 포함하지 않는다.

호스트 전용 설치만으로 바닐라 호환성이 보장되는 것은 아니다. 각 기능이 참가자에게 올바르게 보이고, 같은 게임 상태로 처리되는지 실제 멀티플레이에서 검증한다.

## 난이도 진행

게임의 기존 난이도와 별도로 모드 난이도 단계를 관리한다.

초기 해석은 **3스테이지를 완료할 때마다 다음 스테이지부터 1단계 상승**이다.

| 현재 스테이지 | 모드 난이도 단계 |
| --- | --- |
| 1~3 | 0 — 기본 |
| 4~6 | 1 |
| 7~9 | 2 |
| 10~12 | 3 |
| 13~15 | 4 |
| 16 이상 | 5 — 최대 |

헬파티 난이도는 0~5단계다. 0단계는 순정 상태 그대로 진행하며 모드에 의한 몬스터 강화나 특수 능력을 적용하지 않는다.

현재 스테이지를 1부터 세면 `모드 난이도 단계 = min(5, floor((현재 스테이지 - 1) / 3))`이다.

아래 진행 규칙은 구현 전 검토할 초기안이다.

- 스테이지 실패와 재시도로 난이도 단계를 추가 상승시키지 않는다.
- 같은 진행에서 스테이지를 다시 불러와도 능력을 중복 적용하지 않는다.
- 새 런에서는 모드 난이도를 초기화한다.
- 저장된 런을 이어 할 때의 복원 기준은 게임의 저장·진행 구조를 확인한 뒤 결정한다.

## 몬스터 특수 능력

난이도 단계가 상승할 때 몬스터에게 특수 능력을 추가하는 것이 핵심이다. 단순 수치 강화만으로 전체 기획을 대체하지 않는다.

단계별 대상 몬스터와 추가 능력은 별도 [헬파티 난이도별 몬스터 특수 능력 기획표](docs/monster-abilities.md)에서 관리한다. 각 단계에서는 일부 몬스터만 대상으로 하며, 표에 지정되지 않은 몬스터는 순정 상태를 유지한다.

몬스터별 상세 기획은 [몬스터 기획 폴더](docs/monsters/README.md)의 개별 Markdown 문서에서 관리한다.

초기 구현은 단계별로 정해진 능력을 해금하는 방식으로 시작한다. 능력 풀, 무작위 부여, 중첩 상한과 몬스터별 예외는 호환성 검증 이후 결정한다.

다음은 확정 기능이 아닌 검증 후보다.

| 능력 후보 | 의도 | 확인할 사항 |
| --- | --- | --- |
| 추격 가속 | 추격 중 일정 조건에서 일시적으로 이동 속도 증가 | 호스트의 AI·이동 변경이 참가자 화면에 자연스럽게 반영되는가 |
| 피격 격노 | 피해를 받은 뒤 일정 시간 추격 성능 증가 | 피격 판정의 권한, 발동 중복 방지, 기존 동기화 활용 가능 여부 |
| 동료 경보 | 플레이어를 발견하면 주변 몬스터의 주의를 유도 | 몬스터별 타깃 선정·상태 전이가 호스트 권한으로 가능한가 |

신규 모델, 애니메이션, 효과, 네트워크 메시지가 필요한 능력은 바닐라 참가자의 처리 가능 여부가 확인되기 전까지 채택하지 않는다. 능력의 예고와 발동 표현도 기존 게임 요소로 전달할 수 있는지 확인한다.

## 구현 원칙

1. 게임 버전, 모드 로더, 네트워크 권한 구조와 사용 가능한 API를 먼저 확인한다.
2. 난이도 계산과 능력 선택·적용은 호스트에서만 수행한다.
3. 게임에 이미 존재하는 동기화 경로로 결과를 전달할 수 있는 기능부터 구현한다.
4. 몬스터별 능력 적용 여부를 기록해 중복 강화와 중복 이벤트 등록을 방지한다.
5. 대상 몬스터나 API가 지원되지 않으면 해당 능력을 건너뛰고 원인을 로그로 남긴다.

## 첫 구현 범위

- 호스트 판별과 바닐라 참가자 접속 확인.
- 스테이지 진행 감지와 모드 난이도 계산.
- 호환성을 검증한 특수 능력 1개를 몬스터 1종에 적용.
- 스테이지 전환, 재시도, 몬스터 재생성 시 중복 적용 방지.
- 호스트 로그에 스테이지, 난이도 단계, 능력 적용 결과 기록.

## 호환성 검증 기준

- 모드 설치 호스트와 미설치 참가자가 함께 입장하고 플레이할 수 있다.
- 능력 발동 후 이동, 공격, 피해, 사망 결과가 양쪽에서 일치한다.
- 스테이지 전환과 재시도 이후에도 난이도와 능력이 정확히 적용된다.
- 능력 적용 이후 생성되는 몬스터에도 현재 단계가 적용된다.
- 게임이 중도 참가를 지원하는 경우, 해당 경로에서도 상태가 일치한다.
- 지원하지 않는 몬스터나 능력을 건너뛰어도 런이 계속 진행된다.

## 현재 상태

공용 스테이지 난이도, Apex Predator의 분신·Crown, Animal의 독가스·분화, Birthday Boy의 풍선강화와 Bella의 자폭·미끼를 구현했다. Birthday Boy는 난이도 1부터 풍선 3m·3초 체류 시 자동 파열하며, 일반·자동 파열 순간 주변 10m 안에 플레이어가 있으면 Gnome을 생성한다. 난이도 2에는 자동 파열 시 본체 어그로와 사망 시 최근 잔존 풍선 최대 3개의 Eyeball 보상, 난이도 3에는 비치명 피격 시 본체 주변 10m의 모든 풍선 파열·Gnome 생성이 추가된다. Bella는 난이도 1부터 의자의 Clown Doll을 순정 벨 경고에 연동하고, 난이도 3부터 벨마다 Tiny 미끼를 교체하며 잡은 플레이어를 공격한다. 사망 후 남은 미끼와 인형은 순정 수집품으로 해제한다. Debug는 난이도 5와 시작 위치 근처 Bella·샷건·수면총 생성을 제공한다. Release는 실제 진행도를 따른다. 실행·확인 방법은 [Bella 플레이테스트](docs/bella-playtest.md)를 참고한다. 나머지 몬스터는 기획 단계이며, 바닐라 참가자 호환성은 별도 검증이 필요하다.

개발 환경, 빌드·디버깅·패키징 방법과 검증 범위는 [개발 환경 문서](docs/development.md)를 참고한다.
